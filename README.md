# pi-extensions

Personal [pi](https://pi.dev) coding agent extensions. Installed as a local pi package, so edits are live: change a file, then `/reload` in a pi session.

| `extensions/todo.ts`      | Task tracking (Claude Code `TodoWrite` / Codex `update_plan` pattern). One `todo` tool — every call sends the full list (`content` + `status`: pending/in_progress/completed/cancelled, at most one in_progress) and replaces the old one; invalid lists are rejected with the current state attached so the model self-corrects in one retry, and updates that drop unfinished items are accepted with a note naming them — restructuring (reword, split, abandon) stays friction-free while accidental drops stay visible. Usage policy: the tool exists to make a plan **outlive the context window** (compaction survival, user-visible progress, small-model support), not to organize a capable model's thoughts — so the description tells models to skip it when thinking suffices and to batch status updates at milestones. State snapshots ride in tool-result `details` and are replayed on `session_start`/`session_tree`, so every session branch, rewind, and resume restores the right list. One-shot `before_agent_start` reminders re-inject the plan when it is unfinished and stale (4+ turns) or when compaction wiped it — summaries never carry the plan, so every compaction arms that trigger; mid-run boundary drafts fire no `session_compact` and instead chain a plan message (`todo.plan`) after the compaction entry, which the resume scan recognizes so resumed drafts don't double-inject. Call rows show `todo 2/5 — active item`, `— next: …` when nothing is active, or ` ✓` when all resolved; result rows show progress then the delta — `✓ "a", "b" · ▸ "c" · + "d"` (two names per category, then +N, matched by exact item text) — fall back to the active item when nothing changed, and end with `all resolved` on a finished plan; expand for the full checklist. `/todos` opens the list full-screen. | `extensions/recall.ts`    | Lossless search over compacted-away session history. One `recall` tool: compaction keeps only a summary in context, but pi stores every raw entry forever — this tool makes that archive searchable again. The archive is exact (`getBranch()` minus the ids the session projection still shows — compaction- and context-edit-aware), so archived summaries and edit-omitted entries all fall out of one set-diff. Search ranks line-aligned chunks (~3k chars) with hand-rolled BM25 (identifier-aware: `parseHeader` matches “parse header”) multiplied by a memory-horizon recency decay — scores halve per `PI_RECALL_HALF_LIFE_HOURS` (default 4h) measured from the archive frontier, floored at `PI_RECALL_RECENCY_FLOOR` (default 0.25), so the latest of several decisions about the same topic wins while distinctive old terms stay findable — and returns verbatim excerpts with provenance (role, kind, timestamp, session); `mode: "read"` pages a full entry by ref. `scope: "session"` (default) indexes the in-memory branch on demand; `scope: "project"` adds sibling session files from the cwd-scoped session dir, labeled “past session” and down-ranked (`PI_RECALL_FOREIGN_WEIGHT`, default 0.5) — retrieval is always model-initiated, never injected. A one-shot `before_agent_start` reminder after each compaction tells the model recall exists. The extension also owns the context budget and the summary: auto-compaction fires when projected context exceeds a target — min(256k tokens, 70% of the model's context window), whichever is reached first: an absolute ceiling at the top of the measured 128–256k reasoning-reliability cliff band, scaled down for smaller windows (`PI_RECALL_COMPACT_TARGET` token cap, default 256k — set 10000000 for a purely window-relative target; `PI_RECALL_COMPACT_RATIO` window fraction, default 0.7; token cap 0 disables, and so does a target below what one compaction can achieve, which would re-draft every turn) from two triggers — mid-run `turn_end` boundary drafts (a continuously busy agent never settles; the draft commits before the next request, forces no continuation, aborts nothing, and is summarized in-handler because drafts never fire `session_before_compact`) and `ctx.compact()` from `agent_settled` when idle (`ctx.compact()` starts with `abort()`, so it is only safe once the run is idle) — with pi's near-limit threshold as the remaining backstop; compaction failures (budget trigger or pi-side) append one-line breadcrumbs to `~/.pi/agent/recall-compaction-errors.log`, and every compaction — manual `/compact` included — is summarized by the extension's own complete prompt (pi's built-in summarizer prompt is never involved, so pi-side prompt changes cannot reshape our summaries; template: Goal / Constraints & Preferences / Progress incl. Blocked and Dead Ends — abandoned approaches recorded with their failure reason so a compaction never invites retrying them — / Key Decisions / Next Steps / Critical Context; the prompt names both safety nets up front — pi's raw kept tail (the newest ~keepRecentTokens of messages stay in context verbatim after the summary, newer than everything summarized, so current in-flight work is never restated or inferred; the session_before_compact path reports the resolved per-model setting, drafts pi's default 20k) and recall (detail is re-fetchable on demand) — licensing hard compression; the layout is an instruction sandwich: full template and rules before <conversation>, terse directive after, because some models effectively ignore trailing instructions over long inputs — fleet-measured on mimo-v2.6-flash (0/3 template adherence with instructions after, 3/3 with the sandwich, on near-zero reasoning) and deepseek-v4.1-flash (2/3 → 3/3)), via `session_before_compact` for pi-triggered compactions and the same summarizer inline for drafts: `serializeConversation` + one `ctx.modelRegistry.complete` call — cache-skipped one-off, 24,576-token output cap (sized so reasoning tokens sharing the allocation cannot starve the summary — observed starvation at 8,192 and reasoning outliers past 17k tokens on glm-5.3) and a hard budget under `PI_RECALL_SUMMARY_CHARS` (default 5,000 characters — recall makes the summary a map, not the archive) — transient provider failures retry in place (the same 3-attempt budget pi gives its own summarizer), deterministic failures fall back to pi's default (`PI_RECALL_COMPACT_OWN=0` opts out; drafts have no fallback — a failure costs one turn's wait and the next `turn_end` retries). Summaries stay plan-less by design — current state belongs at the recent position, not frozen at the context front where it would age behind newer todo calls: mid-run boundary drafts (which fire no `session_compact`, so the todo extension's post-compaction reminder can't catch them) chain a plan message (`## Current Plan`, from the todo tool's newest branch snapshot, `todo.plan`) after the compaction entry — after the kept tail, the most recent slot — and pi-triggered compactions lean on the todo reminder instead (recall imports the plan rendering from todo.ts, so vendoring recall.ts alone requires todo.ts too). The full `PI_RECALL_SUMMARY_CHARS` budget goes to the map. Call rows show `recall — query`; result rows show hit count with snippets on expand. Knobs: `PI_RECALL_SCOPE`, `PI_RECALL_FOREIGN_WEIGHT`, `PI_RECALL_HALF_LIFE_HOURS`, `PI_RECALL_RECENCY_FLOOR`, `PI_RECALL_COMPACT_TARGET`, `PI_RECALL_COMPACT_RATIO`, `PI_RECALL_COMPACT_OWN`, `PI_RECALL_SUMMARY_CHARS`, `PI_RECALL_SUMMARY_THINKING` (`off` by default — no thinking is requested and the provider applies its own default (glm-5.3 disables outright, deepseek keeps a light default); the instruction-sandwich layout carries template adherence at literally 0 reasoning tokens — measured across the fleet — so the whole output cap stays available for summary text and no reasoning run can starve it; `session` mirrors the session's level instead, `off | minimal | low | medium | high | xhigh | max`pins it),`PI_RECALL_CHUNK_CHARS`, `PI_RECALL_SNIPPET_CHARS`, `PI_RECALL_MAX_RESULTS`, `PI_RECALL_READ_CHARS`, `PI_RECALL_PROJECT_MAX_MB`. |
| `extensions/overflow.ts`  | Caps oversized custom tool results so one call can't flood the window. pi truncates its built-ins (read/grep/bash cap at ~50 KB; the built-in MCP extension middle-cuts its own text results over 20 KB), but other custom tool results — this package's included — enter context uncapped: a single log dump can cost tens of KB that compaction later compresses away entirely. A `tool_result` handler replaces text content over `PI_OVERFLOW_MAX_CHARS` (default 10,000, floor 1,000, `0` disables; read once at extension load, invalid values fall back to the default) with a banner (original/shown/omitted counts) + head (80%) + tail (20%), cut at a line boundary when one sits near the cut; the full output is stashed beside the session at `<sessionDir>/overflow/<callId>.txt`, so it survives compaction and resume, and the banner points at it (read with offset/limit, or grep — the recall tool doesn't search stash files, it only sees session `.jsonl`s; stashes live with the session directory, so deleting the session reclaims them). For built-in-MCP results over 20 KB the stash holds pi's own middle-cut rather than the original — raise `PI_OVERFLOW_MAX_CHARS` above 20k if that matters. Image parts, `details`, `isError`, and `usage` pass through untouched; built-in tools are skipped by name (mirrors pi's `ToolResultEvent` union — unknown future built-ins just get capped too, harmlessly). Fail-open everywhere: no session dir or a failed stash write leaves the original result alone — the cap never discards output without a recoverable pointer. Note the cap applies to every custom tool, recall's `read` mode included — keep `PI_OVERFLOW_MAX_CHARS` above `PI_RECALL_READ_CHARS` if you raise that knob. ## Design notes

The through-line: **keep the parent agent's context small** and **fail explicitly**. Each extension adds capability without bloating the tool surface the main agent sees, and every network/child boundary is bounded and reports errors with enough detail to act on.

### MCP: use pi's built-in (removed 2026-09)

`extensions/mcp.ts` was removed after pi 0.99.0 shipped MCP support as a built-in extension (`builtin:mcp`) — stdio and streamable HTTP with OAuth, reading the same `~/.pi/agent/mcp.json`. The old `pin: [...]` concept maps to the built-in's per-server `exposure` setting in that file:

- `"exposure": "direct"` — tools declared to the model like built-ins (what `pin` did; use for small, high-value servers like parallel-search)
- `"exposure": "deferred"` — tools stay undeclared until the `tool_search` tool loads them (closest to the old gateway's search-then-call flow; use for large servers like playwright)
- default `"exposure": "codemode"` — tools callable from codemode scripts, kept out of declarations

Manage servers with `/mcp` or `pi mcp add|remove|list|login|logout`.

### Subagents: isolated headless pi runs

- **Isolation**: children run with `--no-extensions --no-skills --no-prompt-templates --no-context-files --no-session`, so they see only their system prompt, the task, and the built-in tools their frontmatter allows — no feedback loop, no context bleed.
- **Delegation contract**: the child's final reply is the only thing the parent sees, so agent prompts push children to make that reply complete and self-contained.
- **Fail closed on tools**: an unknown tool name warns and is dropped; a per-tool map entry with no value disables the tool. A broken restriction never silently widens a child's powers.
- **Bounded**: per-task timeout (`PI_SUBAGENT_TIMEOUT_MS`, default 10m) via a `unref()`'d timer that SIGKILLs; parallel batch concurrency via `PI_SUBAGENT_CONCURRENCY` (default 4); stdout/stderr buffers are capped so a runaway child can't OOM the parent.
- **Slow runs background instead of blocking**: a child still running at `PI_SUBAGENT_BG_AFTER_MS` (default 2m; `background: true` adopts immediately) is adopted into a session-scoped registry (`lib/background.ts`) — the tool result returns at once, the child detaches from the turn's abort signal but not the hard timeout, and its result arrives as exactly one followUp wake carrying the reply (capped, full text stashed at `<sessionDir>/bg/<id>.txt`) and usage. The wake is a real transcript entry, so recall can find it after compaction — no status tool needed. Wakes fire once, failures carry the child's last output and spend, `session_shutdown`/reload kills running children (an orphaned child burns tokens with nobody consuming the result), and batches return partials with per-task wakes; adopted children's usage rides in wake text rather than session totals. Deliberately minimal in shape — every wake is one message, every kill is immediate — informed by Claude Code's production scars (notification storms, unrecoverable completions).
- **Shell commands background too**: the same extension registers a `bg` tool (`lib/background.ts`) that adopts a `bash -c` child into the same registry — one footer count, one shutdown kill, one wake channel. It returns a task id immediately; the wake carries the exit status, duration, and a rolling 8KB combined stdout+stderr tail (over-cap stashed like subagent replies). `timeout_ms` overrides the 10m SIGKILL default (clamped to schedulable range — Node clamps overflow to an instant 1ms kill). Commands run in the session cwd, spawned detached as a process group so kills take out grandchildren too (a surviving grandchild holds the pipe write-ends and would strand the wake). Note: a loadout that excludes pi's built-in bash tool regains a shell surface through `bg` — same privilege, worth knowing.
- **Both sides can intervene**: `/tasks` lists running tasks (id, kind, elapsed); `/tasks kill <id>` kills one and `/tasks kill all` clears the board; the agent has the same lever as the `kill_task` tool (an unknown id errors with the running list). Kills mark the task killed before signaling the child, so its wake never fires — the killer knows, the transcript stays clean. Verb-first subcommands match pi's `/mcp add|remove|list` grammar, and `/tasks` (not `/bg`) stays clear of pi's built-in `/bug`.

### llamswap: resilient model discovery

- Bounded `GET /v1/models` (15s). On a gateway blip, fall back to the last persisted catalog so the provider keeps working; only throw if there is no cached catalog at all.

### recall: archive without a database

- **The session file is the store.** pi already persists every raw entry (branch tree, tool results, thinking blocks) and compaction only changes the projection — so the archive is a set-diff (`getBranch()` minus the ids the session projection still shows), branch- and rewind-correct by construction; entries omitted by context edits stay searchable because omitted entries project no messages. No index files, no sidecar state, nothing to invalidate.
- **Session scope is built per call from memory** and thrown away — always fresh, tens of milliseconds at multiday-session scale. Project scope lazily parses sibling `.jsonl` files from the cwd-scoped session dir into an in-memory corpus (LRU-capped by bytes, mtime/size-validated, per-call `stat()` recheck); the current session's own file is skipped because the in-memory branch already covers it correctly.
- **Lexical search on purpose.** BM25 over verbatim text is the regime where models are strongest (literal match, no latent-association weakness), code-agent queries are naturally lexical (paths, symbols, error strings), and every hit carries provenance so foreign-session material is visible as such. Foreign chunks are down-ranked by a configurable weight rather than hidden — a strongly relevant past-session hit can still surface.
- **Recency is a memory horizon, not a timestamp tiebreak.** Scores decay exponentially (`0.5^(age/halfLife)`, floored) so the newest of several decisions about the same topic outranks older, wordier discussions of it — mirroring how memory actually fades. Age is measured from the archive frontier (the newest chunk in the searched corpus), never wall clock, so weekends and sporadic projects don't distort ordering (Monday's query ranks Friday's last decision above Friday's first), repeated queries are deterministic, and a rare distinctive term from days back still surfaces because idf-driven relevance beats the floor. Set `PI_RECALL_RECENCY_FLOOR=1` to disable.
- **Own the budget and the summary.** Compaction is the one sanctioned prefix rewrite; recall makes it cheap, so the extension drives it deliberately. Auto-compaction targets a context budget — min(256k tokens, 70% of the model's window), whichever is reached first: an absolute ceiling at the top of the measured 128–256k reliability-cliff band, scaled down for smaller windows (cache economics still favor compact steady-states over near-limit thrash) — instead of pi's near-limit default, from two triggers: `turn_end` boundary drafts mid-run (a continuously busy agent never settles — one long run can climb from the target to pi's near-limit backstop with a settled-only trigger dormant; the draft commits before the next request, no continuation is forced, nothing is aborted, and the summary is generated in-handler because drafts carry extension content) and `ctx.compact()` from `agent_settled` when idle (nothing to abort or race; calling it from `before_agent_start` deadlocks/races the run being started), with pi's threshold kept as the remaining backstop; a draft failure costs one turn's wait and the next `turn_end` retries. Compaction failures are never silent: budget-trigger `onError`, pi's `session_compact_failed`, and every summary-ownership fallback (summarizer error, output cap, empty text, missing model) append one-line breadcrumbs to `~/.pi/agent/recall-compaction-errors.log`; an aborted signal (user cancel) stays silent. Summary generation is owned end to end via `session_before_compact` (and the same summarizer for drafts): our prompt is the only prompt — `serializeConversation(convertToLlm(...))` over the chronological span (older spans, then split-turn prefix), one `ctx.modelRegistry.complete` call with pi's own summarizer conventions (`cacheRetention: "none"`, fresh session id, abortable, thinking not requested by default — the provider's own default applies (glm-5.3 disables outright, deepseek thinks lightly), the sandwich layout holds template adherence at 0 reasoning tokens across the fleet, and nothing can starve the output cap from the reasoning side — forwarded only when the model reasons and a level is set, `PI_RECALL_SUMMARY_THINKING` pins a level or mirrors the session's) and our own `maxTokens` 24,576 (room for reasoning tokens, which share the allocation; outliers past 17k observed) clamped to the model's declared cap; error/aborted/length-stopped and tool-call responses are rejected the way pi's summarizer rejects them (a partial text must never become the session checkpoint). Transient provider failures retry in place (three attempts, exponential backoff, abort-aware — the same confidence pi shows in its own summarizer, which gets the identical `maxRetries ?? 3`); only deterministic failures fall back to pi's default — a working map, not an archive: the prompt states pi's two safety nets — the raw kept tail (newest ~keepRecentTokens stay in context verbatim after the summary, newer than everything summarized, so in-flight work is never restated or inferred — the kept context wins on conflict) and recall (the transcript stays searchable, so detail is retrievable on demand) — exact paths/identifiers/errors as recall anchors, a hard output budget (under `PI_RECALL_SUMMARY_CHARS`, default 5,000 characters — recall makes the summary orientation, not the record; when tight, Done detail compresses first) because a length-stopped generation is discarded whole, and Next Steps as the resume bridge: ordered queue from where the summarized span ends, specific enough to resume cold — the kept tail already shows the in-flight work. The prompt is an instruction sandwich — full template and rules before the conversation, terse directive after — fleet-measured across glm-5.3, deepseek-v4.1-flash, and mimo-v2.6-flash: trailing-instruction layouts lose whole model families (mimo 0/3, 400-char stubs), the sandwich holds (3/3) even on near-zero reasoning, and cuts glm-5.3's reasoning usage ~60%. File lists are carried forward in pi's `details` shape, and any failure returns `undefined` so pi's default summarizer runs instead — custom compaction can never block compaction.
- **Summaries are indexed as maps.** Compaction/branch-summary entries enter the archive (and the index) exactly when a later compaction folds them out of context — the set-diff decides, no special cases. Hits are labeled as digests so the model treats them as a table of contents and drills into raw entries.
- **Cache invariants hold by construction.** A plain tool whose results ride at the tail; the wire transcript stays append-only, the system prompt gains one `promptSnippet` line, and nothing ever rewrites sent messages. The only prefix rewrite in the system remains pi's own compaction.
- **Bounded everywhere.** Snippets and reads are char-capped with explicit continuation refs; project corpora are byte-capped; unreadable session files are skipped and reported, never fatal.

## Development

```sh
npm install        # once
npm run check      # typecheck (with lint-grade strict flags) + full test suite
npm test           # vitest only
npx tsc --noEmit   # typecheck only
```

Pure logic (config parsing, frontmatter splitting, tool-name resolution, result serialization) is exported separately and covered by vitest suites in `tests/`; the spawn boundary is injected so child runs are testable without launching pi.

pi loads the TypeScript directly; the dev dependency on `@earendil-works/pi-coding-agent` (pinned to the installed pi version) provides the types at edit time.

## Wiring

```sh
pi install /Users/nchapman/Code/pi-extensions   # one-time; loads in-place

```
