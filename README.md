# pi-extensions

Personal [pi](https://pi.dev) coding agent extensions. Installed as a local pi package, so edits are live: change a file, then `/reload` in a pi session.

## Extensions

| Extension | Description |
|---|---|
| `extensions/mcp.ts` | MCP gateway on `@modelcontextprotocol/sdk`. One proxy tool: status, list, search, describe, call. Servers from `~/.pi/agent/mcp.json` connect lazily, tool metadata is cached, connections close on idle (`unref`'d timer + `session_shutdown`) so pi can always exit. Tool-call rows show the call mode (`mcp search "query"`, `mcp call server__tool`). |
| `extensions/subagents.ts` | Subagent delegation. Agents are markdown files in `~/.pi/agent/agents/` (YAML frontmatter via the `yaml` package: `description`, `tools` as string/array/per-tool map, optional `model`/`thinking`). `subagent` runs one task; `subagents` runs a batch in parallel. Children are headless pi runs (`pi -p --mode json`) with isolated context, custom system prompt, and restricted tools. Pass `agent_md` for an ad-hoc specialist; with neither `agent` nor `agent_md`, a read-only generic investigator runs. Each agent also gets a matching `/name` slash command — `/name task` sends a user message that delegates `task` to that subagent (names colliding with pi built-ins or duplicates are skipped with a warning). Tool-call rows show the agent name (`subagent code-reviewer — task…`; batches show `subagents (n) names`); result rows show `running (agent)` with the streamed tail, then `done (agent) — first line` with the full reply on expand (`failed (agent) — error` on error). Timeout via `PI_SUBAGENT_TIMEOUT_MS` (default 10m); parallelism via `PI_SUBAGENT_CONCURRENCY` (default 4). |
| `extensions/llamswap.ts` | Registers the local `yeti` and `spark` llamswap gateways (OpenAI-compatible) with dynamic model discovery via `GET /v1/models`. Bounded fetch (15s) with fallback to the last persisted catalog on gateway blips. Gateway hosts/ports are hardcoded constants — edit `PROVIDERS` at the top of the file to repoint. |
| `extensions/todo.ts` | Task tracking (Claude Code `TodoWrite` / Codex `update_plan` pattern). One `todo` tool — every call sends the full list (`content` + `status`: pending/in_progress/completed/cancelled, at most one in_progress) and replaces the old one; invalid lists are rejected with the current state attached so the model self-corrects in one retry, and updates that drop unfinished items are accepted with a note naming them — restructuring (reword, split, abandon) stays friction-free while accidental drops stay visible. Usage policy: the tool exists to make a plan **outlive the context window** (compaction survival, user-visible progress, small-model support), not to organize a capable model's thoughts — so the description tells models to skip it when thinking suffices and to batch status updates at milestones. State snapshots ride in tool-result `details` and are replayed on `session_start`/`session_tree`, so every session branch, rewind, and resume restores the right list. One-shot `before_agent_start` reminders re-inject the plan when it is unfinished and stale (4+ turns) or when compaction wiped it — but a compaction summary that already embeds the plan disarms the compaction trigger, so that trigger never re-injects the identical list. Recall-owned compaction summaries embed the plan verbatim (`## Current Plan`) for exactly this reason, including mid-run boundary drafts, which fire no `session_compact` for the reminder to catch. Call rows show `todo 2/5 — active item`; result rows show progress collapsed and the full checklist on expand. `/todos` opens the list full-screen. |
| `extensions/recall.ts` | Lossless search over compacted-away session history. One `recall` tool: compaction keeps only a summary in context, but pi stores every raw entry forever — this tool makes that archive searchable again. The archive is exact (`getBranch()` minus the ids the session projection still shows — compaction- and context-edit-aware), so archived summaries and edit-omitted entries all fall out of one set-diff. Search ranks line-aligned chunks (~3k chars) with hand-rolled BM25 (identifier-aware: `parseHeader` matches “parse header”) multiplied by a memory-horizon recency decay — scores halve per `PI_RECALL_HALF_LIFE_HOURS` (default 4h) measured from the archive frontier, floored at `PI_RECALL_RECENCY_FLOOR` (default 0.25), so the latest of several decisions about the same topic wins while distinctive old terms stay findable — and returns verbatim excerpts with provenance (role, kind, timestamp, session); `mode: "read"` pages a full entry by ref. `scope: "session"` (default) indexes the in-memory branch on demand; `scope: "project"` adds sibling session files from the cwd-scoped session dir, labeled “past session” and down-ranked (`PI_RECALL_FOREIGN_WEIGHT`, default 0.5) — retrieval is always model-initiated, never injected. A one-shot `before_agent_start` reminder after each compaction tells the model recall exists. The extension also owns the context budget and the summary: auto-compaction fires when projected context exceeds a target (default 128k — below the reasoning-reliability cliff; `PI_RECALL_COMPACT_TARGET`, 0 disables) from two triggers — mid-run `turn_end` boundary drafts (a continuously busy agent never settles; the draft commits before the next request, forces no continuation, aborts nothing, and is summarized in-handler because drafts never fire `session_before_compact`) and `ctx.compact()` from `agent_settled` when idle (`ctx.compact()` starts with `abort()`, so it is only safe once the run is idle) — with pi's near-limit threshold as the remaining backstop; compaction failures (budget trigger or pi-side) append one-line breadcrumbs to `~/.pi/agent/recall-compaction-errors.log`, and every compaction — manual `/compact` included — is summarized by the extension's own complete prompt (pi's built-in summarizer prompt is never involved, so pi-side prompt changes cannot reshape our summaries; template: Goal / Constraints & Preferences / Progress incl. Blocked and Dead Ends — abandoned approaches recorded with their failure reason so a compaction never invites retrying them — / Key Decisions / Next Steps / Critical Context), via `session_before_compact` for pi-triggered compactions and the same summarizer inline for drafts: `serializeConversation` + one `ctx.modelRegistry.complete` call — cache-skipped one-off, 8,192-token output cap (a backstop, not a target — reasoning tokens share it) and a hard budget under `PI_RECALL_SUMMARY_CHARS` (default 5,000 characters — recall makes the summary a map, not the archive) — transient provider failures retry in place (the same 3-attempt budget pi gives its own summarizer), deterministic failures fall back to pi's default (`PI_RECALL_COMPACT_OWN=0` opts out; drafts have no fallback — a failure costs one turn's wait and the next `turn_end` retries). Every owned summary carries the current todo plan verbatim as a `## Current Plan` section, read from the todo tool's newest branch snapshot — boundary drafts fire no `session_compact`, so the todo extension's post-compaction reminder can't catch them and the summary is the plan's immediate carrier — with the section's length deducted from the `PI_RECALL_SUMMARY_CHARS` budget (recall imports this from todo.ts, so vendoring recall.ts alone requires todo.ts too); carrying the plan also disarms todo's post-compaction reminder — the section's marker is the signal that the plan is already in context. Call rows show `recall — query`; result rows show hit count with snippets on expand. Knobs: `PI_RECALL_SCOPE`, `PI_RECALL_FOREIGN_WEIGHT`, `PI_RECALL_HALF_LIFE_HOURS`, `PI_RECALL_RECENCY_FLOOR`, `PI_RECALL_COMPACT_TARGET`, `PI_RECALL_COMPACT_OWN`, `PI_RECALL_SUMMARY_CHARS`, `PI_RECALL_SUMMARY_THINKING` (`session` mirrors the session's level — default; or `off|minimal|low|medium|high|xhigh|max` to pin it, `off` disables thinking at the API level and frees the whole output cap for summary text), `PI_RECALL_CHUNK_CHARS`, `PI_RECALL_SNIPPET_CHARS`, `PI_RECALL_MAX_RESULTS`, `PI_RECALL_READ_CHARS`, `PI_RECALL_PROJECT_MAX_MB`. |
| `extensions/overflow.ts` | Caps oversized MCP/custom tool results so one call can't flood the window. pi truncates its built-ins (read/grep/bash cap at ~50 KB), but MCP and other custom tool results enter context uncapped — a single Playwright snapshot or log dump can cost tens of KB that compaction later compresses away entirely. A `tool_result` handler replaces text content over `PI_OVERFLOW_MAX_CHARS` (default 10,000, floor 1,000, `0` disables; read once at extension load, invalid values fall back to the default) with a banner (original/shown/omitted counts) + head (80%) + tail (20%), cut at a line boundary when one sits near the cut; the full output is stashed beside the session at `<sessionDir>/overflow/<callId>.txt`, so it survives compaction and resume, and the banner points at it (read with offset/limit, or grep — the recall tool doesn't search stash files, it only sees session `.jsonl`s; stashes live with the session directory, so deleting the session reclaims them). Image parts, `details`, `isError`, and `usage` pass through untouched; built-in tools are skipped by name (mirrors pi's `ToolResultEvent` union — unknown future built-ins just get capped too, harmlessly). Fail-open everywhere: no session dir or a failed stash write leaves the original result alone — the cap never discards output without a recoverable pointer. Note the cap applies to every custom tool, recall's `read` mode included — keep `PI_OVERFLOW_MAX_CHARS` above `PI_RECALL_READ_CHARS` if you raise that knob. |

## Design notes

The through-line: **keep the parent agent's context small** and **fail explicitly**. Each extension adds capability without bloating the tool surface the main agent sees, and every network/child boundary is bounded and reports errors with enough detail to act on.

### MCP: one proxy tool, lazy connections
- **Context cost**: a single `mcp` tool in context instead of every server's full tool schema. Discover with `search`, inspect with `describe`, call with `tool: "server__tool"`. Bare names work when unambiguous; ambiguous names list their qualified options.
- **Lazy connect**: servers connect on first use — a targeted call connects only the server it needs, while `search`/`describe` connect all to build the index. Tool metadata is cached after the first connect.
- **Clean exit**: idle connections close after 30s via an `unref()`'d timer, and all clients close on `session_shutdown`, so open MCP servers never keep pi alive.
- **Bounded everywhere**: connect (20s), list (20s), and call (120s) are each wrapped in a timeout; in-flight calls are tracked so an idle close never fires mid-call.

### Subagents: isolated headless pi runs
- **Isolation**: children run with `--no-extensions --no-skills --no-prompt-templates --no-context-files --no-session`, so they see only their system prompt, the task, and the built-in tools their frontmatter allows — no feedback loop, no context bleed.
- **Delegation contract**: the child's final reply is the only thing the parent sees, so agent prompts push children to make that reply complete and self-contained.
- **Fail closed on tools**: an unknown tool name warns and is dropped; a per-tool map entry with no value disables the tool. A broken restriction never silently widens a child's powers.
- **Bounded**: per-task timeout (`PI_SUBAGENT_TIMEOUT_MS`, default 10m) via a `unref()`'d timer that SIGKILLs; parallel batch concurrency via `PI_SUBAGENT_CONCURRENCY` (default 4); stdout/stderr buffers are capped so a runaway child can't OOM the parent.

### llamswap: resilient model discovery
- Bounded `GET /v1/models` (15s). On a gateway blip, fall back to the last persisted catalog so the provider keeps working; only throw if there is no cached catalog at all.

### recall: archive without a database
- **The session file is the store.** pi already persists every raw entry (branch tree, tool results, thinking blocks) and compaction only changes the projection — so the archive is a set-diff (`getBranch()` minus the ids the session projection still shows), branch- and rewind-correct by construction; entries omitted by context edits stay searchable because omitted entries project no messages. No index files, no sidecar state, nothing to invalidate.
- **Session scope is built per call from memory** and thrown away — always fresh, tens of milliseconds at multiday-session scale. Project scope lazily parses sibling `.jsonl` files from the cwd-scoped session dir into an in-memory corpus (LRU-capped by bytes, mtime/size-validated, per-call `stat()` recheck); the current session's own file is skipped because the in-memory branch already covers it correctly.
- **Lexical search on purpose.** BM25 over verbatim text is the regime where models are strongest (literal match, no latent-association weakness), code-agent queries are naturally lexical (paths, symbols, error strings), and every hit carries provenance so foreign-session material is visible as such. Foreign chunks are down-ranked by a configurable weight rather than hidden — a strongly relevant past-session hit can still surface.
- **Recency is a memory horizon, not a timestamp tiebreak.** Scores decay exponentially (`0.5^(age/halfLife)`, floored) so the newest of several decisions about the same topic outranks older, wordier discussions of it — mirroring how memory actually fades. Age is measured from the archive frontier (the newest chunk in the searched corpus), never wall clock, so weekends and sporadic projects don't distort ordering (Monday's query ranks Friday's last decision above Friday's first), repeated queries are deterministic, and a rare distinctive term from days back still surfaces because idf-driven relevance beats the floor. Set `PI_RECALL_RECENCY_FLOOR=1` to disable.
- **Own the budget and the summary.** Compaction is the one sanctioned prefix rewrite; recall makes it cheap, so the extension drives it deliberately. Auto-compaction targets a context budget (default 128k — the reliability cliff is 128–256k, and cache economics favor compact steady-states over near-limit thrash) instead of pi's near-limit default, from two triggers: `turn_end` boundary drafts mid-run (a continuously busy agent never settles — one long run can climb from the target to pi's near-limit backstop with a settled-only trigger dormant; the draft commits before the next request, no continuation is forced, nothing is aborted, and the summary is generated in-handler because drafts carry extension content) and `ctx.compact()` from `agent_settled` when idle (nothing to abort or race; calling it from `before_agent_start` deadlocks/races the run being started), with pi's threshold kept as the remaining backstop; a draft failure costs one turn's wait and the next `turn_end` retries. Compaction failures are never silent: budget-trigger `onError`, pi's `session_compact_failed`, and every summary-ownership fallback (summarizer error, output cap, empty text, missing model) append one-line breadcrumbs to `~/.pi/agent/recall-compaction-errors.log`; an aborted signal (user cancel) stays silent. Summary generation is owned end to end via `session_before_compact` (and the same summarizer for drafts): our prompt is the only prompt — `serializeConversation(convertToLlm(...))` over the chronological span (older spans, then split-turn prefix), one `ctx.modelRegistry.complete` call with pi's own summarizer conventions (`cacheRetention: "none"`, fresh session id, abortable, thinking level forwarded only when the model reasons — `PI_RECALL_SUMMARY_THINKING` pins it instead, `off` disables it API-level) and our own `maxTokens` 8192 clamped to the model's declared cap; error/aborted/length-stopped and tool-call responses are rejected the way pi's summarizer rejects them (a partial text must never become the session checkpoint). Transient provider failures retry in place (three attempts, exponential backoff, abort-aware — the same confidence pi shows in its own summarizer, which gets the identical `maxRetries ?? 3`); only deterministic failures fall back to pi's default — a working map, not an archive: exact paths/identifiers/errors as recall anchors, brevity for the past because the transcript stays searchable, a hard output budget (under `PI_RECALL_SUMMARY_CHARS`, default 5,000 characters — recall makes the summary orientation, not the record; when tight, Done detail compresses first) because a length-stopped generation is discarded whole, and Next Steps treated as unrecoverable: in-flight action first, ordered queue, specific enough to resume cold. File lists are carried forward in pi's `details` shape, and any failure returns `undefined` so pi's default summarizer runs instead — custom compaction can never block compaction.
- **Summaries are indexed as maps.** Compaction/branch-summary entries enter the archive (and the index) exactly when a later compaction folds them out of context — the set-diff decides, no special cases. Hits are labeled as digests so the model treats them as a table of contents and drills into raw entries.
- **Cache invariants hold by construction.** A plain tool whose results ride at the tail; the wire transcript stays append-only, the system prompt gains one `promptSnippet` line, and nothing ever rewrites sent messages. The only prefix rewrite in the system remains pi's own compaction.
- **Bounded everywhere.** Snippets and reads are char-capped with explicit continuation refs; project corpora are byte-capped; unreadable session files are skipped and reported, never fatal.

## Development

```sh
npm install        # once
npm run check      # typecheck (with lint-grade strict flags) + full test suite
npm test           # vitest only
npx tsc --noEmit   # typecheck only
```

Pure logic (config parsing, frontmatter splitting, tool-name resolution, result serialization) is exported separately and covered by vitest suites in `tests/`; the spawn boundary is injected so child runs are testable without launching pi.

pi loads the TypeScript directly; the dev dependency on `@earendil-works/pi-coding-agent` (pinned to the installed pi version) provides the types at edit time.

## Wiring

```sh
pi install /Users/nchapman/Code/pi-extensions   # one-time; loads in-place
pi list                                          # verify
```
